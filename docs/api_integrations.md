# API Integrations

This section details the external API integrations used by the AI-enhanced CV system, including authentication methods, key endpoints, and important considerations for their usage.

## GitHub API

The GitHub API is central to the system's ability to collect real-time activity data and professional metrics. The `activity-collector.js` script interacts with this API (GraphQL and REST).

### Authentication

Authentication to the GitHub API is performed using a Personal Access Token (PAT) provided via the `GITHUB_TOKEN` environment variable. This token should have the necessary scopes to read user and repository data.

*   **Environment Variable**: `GITHUB_TOKEN`
*   **Scope Requirements**: Typically `public_repo` or `repo` (for private repositories) and `read:user`.

### Key Endpoints Used

`activity-collector.js` makes requests to the following primary endpoints:

*   **GraphQL `contributionsCollection`**: One GraphQL query retrieves the contribution calendar (~9 months, for the heatmap), total commit contributions, and per-repository commit totals.
*   **`/users/:username/repos`**: Fetches the repository inventory and language mix.
    *   Parameters: `per_page=100`, `sort=pushed`.
*   **`/users/:username/events/public`**: Retrieves public push events used to build the per-repo commit timeline (up to 3 pages).
    *   Parameters: `per_page=100`.
*   **`/search/commits`**: Cross-repo commit count authored in the lookback window (`author:<user> committer-date:><since>`).

### Rate Limiting Considerations

The collector is deliberately frugal: one GraphQL query plus a handful of REST calls per daily run, well within the authenticated rate limits. A failed call aborts the run with a non-zero exit rather than retrying aggressively.

## AI Provider APIs

AI content proposals are generated by `enhance.js` through the provider-neutral client in `.github/scripts/ai/client.js`. No provider SDKs are used — each provider is a plain HTTPS chat-completion call. The Anthropic Claude API integration used by earlier versions of this system has been retired.

### Providers and Authentication

The provider is selected via `AI_PROVIDER` (with `AI_MODEL` for the model) or auto-detected from which credential is present:

*   **OpenRouter** (CI default): `OPENROUTER_API_KEY`; default model `deepseek/deepseek-v4-flash`.
*   **Ollama** (local development): `OLLAMA_HOST`.
*   **Gemini**: `GEMINI_API_KEY`.

If no provider is configured, the enhancement stage reports `SKIPPED` and the pipeline still validates, renders, and deploys curated content.

### Token Usage

Token usage is **measured**, not estimated: `enhance.js` records the provider-reported input/output token counts in `data/ai-enhancements.json`. There is no response caching layer and no AI budget mechanism — a run makes a handful of small per-section requests.

## Python External API Wrappers

This section details the Python wrappers for external APIs, located in `src/python/api_wrappers/external_apis.py`. **These wrappers are an unintegrated/experimental utility**: they are exercised only by mocked unit tests and are not called by any workflow or JavaScript in the running system. They are documented here as a standardized pattern for interacting with third-party services (firmographics, funding information) if integrated. Note that `external_apis.py` imports `requests`, which must be present in `requirements.txt` for the module to run.

### Abstract API (Firmographics)

**Purpose**: Used to retrieve firmographics data (e.g., company size, industry, location) based on a company domain.

**Class**: `AbstractApiWrapper`

**Authentication**: Requires an API key, which can be provided during initialization or set as an environment variable.

*   **Environment Variable**: `ABSTRACT_API_KEY`

**Key Method**: `get_company_info(domain)`

*   **Description**: Fetches company information for the given domain.
*   **Parameters**: `domain` (string) - The domain name of the company (e.g., "google.com").
*   **Returns**: A dictionary containing company information, or `None` if the request fails.

### Intellizence API (Funding Data)

**Purpose**: Used to retrieve startup funding data.

**Class**: `IntellizenceApiWrapper`

**Authentication**: Requires an API key, which can be provided during initialization or set as an environment variable.

*   **Environment Variable**: `INTELLIZENCE_API_KEY`

**Key Method**: `get_funding_data(query_params=None)`

*   **Description**: Fetches funding data based on specified query parameters.
*   **Parameters**: `query_params` (dictionary, optional) - A dictionary of parameters to filter the funding data (e.g., `{'country': 'USA', 'limit': 10}`).
*   **Returns**: A dictionary containing funding data, or `None` if the request fails.

**Important Note**: For both wrappers, it is highly recommended to manage API keys securely using environment variables rather than hardcoding them in the application code.
